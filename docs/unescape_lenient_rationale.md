# 反转义宽松处理（0x3D）方案 A —— 决策说明

状态：**用户 2026-11 裁决，方案 A（放宽 0x3D，保持 0x3E 严格定界）**。本文件是永久说明，防止后续被悄悄改回严格。

## 为什么放宽

现场模块（南网 STA）在帧尾附带 ASCII 调试日志时，**不对 `=`（0x3D）转义**。严格实现会把整帧判为「非法或悬空的 0x3D 转义」并 DROP，导致连 FC 都无法解析——用户看到的正是「FC CRC 正确却不解析」。

## 实证锚点

线上帧 766 字节（`0x3C@0 … 0x3E@764`），反转义后帧体 763 字节，共 **8 处非法 `0x3D`**：

| 转义流偏移 | 后接字节 | 上下文 |
|---|---|---|
| 453 | 0x32 | `el is op=2,ch=` |
| 458 | 0x35 | ` op=2,ch=54` |
| 485 | 0x30 | `set] RSR=0x10` |
| 587 | 0x30 | `! mcause=0x1` |
| 596 | 0x30 | `0x1 mepc=0x0` |
| 606 | 0x30 | `x0 mtval=0x0` |
| 613 | 0x30 | `l=0x0 ra=0x0` |
| 620 | 0x30 | `a=0x0 sp=0x28` |

**8 处全部非法**；而真正的 PB/MSDU 区域（前 178 字节）内 **0 处** `0x3D` ⇒ 放宽不会污染协议内容。

fixture：`unit_test/frames/frame-probe/nw_log_tail_wire_escaped.bin`（766 字节原样）。

## 现行规则（`src/io/playbackwriter.h:unescape_frame_data`）

1. `0x3D` 后接 `C1/C2/C3` ⇒ 正常还原为 `3C/3D/3E`（不变）
2. `0x3D` 后接其它字节 ⇒ `0x3D` 当普通数据输出，`++lenient_count`，后继字节继续正常处理
3. `0x3D` 悬空在流末尾 ⇒ 输出 `0x3D` 本身，`++lenient_count`
4. 函数**恒返回 true**（保留 bool 签名与两个重载，4 个调用点无需改）
5. **`0x3E` 定界维持严格不变** —— 帧边界仍只由 `0x3E` 判定，这一条不放宽

上层 `serialreader.cpp` 检测到 `lenient_fixes > 0` 时只发一条 warn 级诊断
（`反转义宽松处理 %1 处非法 0x3D（当普通数据）`），**不再 DROP**，帧照常进入解析。

## 禁止改回严格

**⚠ 禁止改回严格。** 改回会导致这类现场帧（模块帧尾带未转义 ASCII 调试日志）全部丢失、
FC/MSDU 全不解析，直接复现用户本次报告的问题。

如需收紧，必须先满足其一：
- 恢复现场帧的可解析性；或
- 提供显式开关（默认宽松），让用户可自行选择严格模式。

否则不得直接改回严格。回归探针见
`unit_test/protocol-nw/msdu-crc-gate-probe/`（W1–W6，已接 CI），任何人改回严格都会让
`W1a/W1c/W5a/W6` 变红，门禁兜底。
