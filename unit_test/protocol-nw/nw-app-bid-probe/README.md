# nw-app-bid-probe

南网应用层**业务标识(表9)**与**传输方向(表8)**回归探针。

## 依据

《通感一体化低压电力线宽带载波通信 SPLC 规约 第5部分 应用层（试行）》

- **6.3.2 表9 业务标识**：必须按 **(报文端口号, 业务标识) 联合判定**，不能只看 BID
- **6.3.1.6 表8 传输方向位**：D15=0 下行、D15=1 上行

表9「数据传输」四个合法组合（其余组合表9 标 `-` = 保留）：

| 端口号 | 业务标识 | 业务名 |
|---|---|---|
| 0x11 | 0x00 | 数据透传至设备 |
| 0x13 | 0x01 | 数据透传至模块 |
| 0x11 | 0x02 | 并发抄读端设备 |
| 0x13 | 0x03 | 站点间通信 |

> `nw_2021` 侧沿用 SPLC 表9（南网 2021 应用层分册本地缺，现有 0x00/0x01 注释与 SPLC 表9 一致，待原文复核）。

## 断言

`nw_2026` 与 `nw_2021` 各跑一遍（两者 `parse_app` 同构）：

1. 四个合法组合 → `summary` / `MSDU Type` 节点 / `BusinessID` 节点三处都含
   `(BID=0x03 站点间通信 ↓)`（或对应值，上行时箭头为 `↑`）
2. 非法组合 `0x11/0x01`、`0x13/0x00`、`0x13/0x02`、`0x11/0x03` → 只显示 `(BID=0xNN)`，
   不带业务名、不带方向符号
3. 载荷仍是**单个 `APP Data` 节点**（业务数据单元不拆解，防越界改动）

## 构造方式

走 `parse_single_hop` 的 `msdu_type==1` 分支（表113 单跳 MAC 头 4B + APP 载荷 + 4B CRC32 占位），
与真实单跳应用帧同一条路径，`parse_app` 不被旁路绕过。

> 注意：单跳帧的 `MSDU Type` 字段位于 `MAC Header [4B]` **子节点**内，
> 填充释义必须递归遍历，只扫顶层会漏（探针已覆盖该路径）。

## 端口门（表9 的"三元组"判定：帧类型 × 报文端口号 × 业务标识）

端口与业务标识不匹配的组合在表9 中标 `-`，属**保留**，不得显示业务名（只显示裸 `BID`，且不带方向箭头）。
覆盖的帧类型：

| 帧类型 | 端口 0x11 | 端口 0x13 |
|---|---|---|
| 确认/否认 0x0 | 0x00 确认、0x01 否认 | — （保留） |
| 数据传输 0x1 | 0x00 数据透传至设备、0x02 并发抄读端设备 | 0x01 数据透传至模块、0x03 站点间通信 |
| 命令 0x2 | 0x00/0x01/0x04/0x05/0x06/0x10/0xF0、0x02 文件传输、0x03 允许·禁止从节点事件 | 0x07/0x08/0x09 |
| 主动上报 0x3 | 0x00 电表事件、0x02 设备事件 | 0x01 停上电事件、0x02 通信模块事件 |
| 抄控器 0x4 | 0x00 抄控器-CCO协议、0x01 数据透传串口转发 | — （保留） |
| 广播命令 0x5 | 0x04 从节点重启、0x05 从节点信息查询 | 0x07/0x08 |
| 数据订阅 0x6 | 0x00 数据订阅业务 | — （保留） |

探针对上表**每个组合正反两侧都断言**（正确端口 → 业务名 + `↓`；错端口 → 裸 `BID` 且无箭头）。
